Clojure · tech.ml.dataset · Apache 2.0

Ask questions of your data with one function.

Datajure gives Clojure a compact query language for tables. Filter rows, add columns, group, aggregate and run window functions with a single function, dt, and a few keywords. Every result is an ordinary dataset.

Get started Read the docs
REPL
(dt prices
    :where #dt/e (> :volume 1000)  ; busy days only
    :by    [:sym]                  ; one group per stock
    :agg   {:days      nrow        ; count the rows
            :avg-price #dt/e (mn :price)})
Result
:sym:days:avg-price
AAPL3102.0
MSFT2202.5

One query function

:where, :set, :agg, :by and a few more keywords cover filtering, new columns, grouping and sorting.

Made for time series

Returns, lags, moving averages, fills, bars, as-of and window joins, inspired by q/kdb+.

Expressions are values

Write #dt/e (* :price :volume) once, store it in a var and reuse it across queries.

Safe with missing data

Comparisons with a missing value are false and aggregations skip it, so blank cells don’t derail a query.

Fast, not magic

Expressions compile to vectorized column operations on tech.ml.dataset. Datajure adds syntax, not a new engine.

Errors that help

A typo such as :prcie is caught before the query runs, with a suggestion: did you mean :price?

See It in Action

The examples use prices, a small table of daily prices for two stocks, defined in the quick start. Every output on this site comes from running the code.

Compute within Groups

Daily returns per stock, in date order. Every row is kept:

(dt prices
    :by [:sym]
    :within-order [(asc :date)]
    :set {:ret #dt/e (- (win/ratio :price) 1)})

Chain Steps

Each dt call returns a dataset, so steps chain with ->. Returns, then their mean and volatility per stock, then a sort:

(-> prices
    (dt :by [:sym] :within-order [(asc :date)]
        :set {:ret #dt/e (- (win/ratio :price) 1)})
    (dt :by [:sym] :agg {:mean-ret #dt/e (mn :ret) :vol #dt/e (sd :ret)})
    (dt :order-by [(desc :mean-ret)]))

The Core Idea

Two keywords decide what a query does to the rows. :set adds columns and keeps every row; :agg collapses rows into summaries. :by splits the rows into groups first. Together they give four operations:

without :by
with :by
:set
:setAdd a column→Same rows, plus new columns.
:set + :byCompute per group→Same rows; each group computed on its own, e.g. returns per stock.
:agg
:aggSummarize everything→One row in total.
:agg + :bySummarize per group→One row per group.

Around that core, :where filters rows first, and :select, :order-by and :take shape the result. The docs explain each step.

Why Datajure

Datajure is a syntax layer, not an engine. It compiles #dt/e expressions to vectorized operations on tech.ml.dataset, so results are standard datasets that work with tablecloth, Clerk, Clay and the rest of the Scicloj ecosystem.

Its design borrows from whichever library got a given idea right:

  • R's data.table: DT[i, j, by] becomes (dt ds :where i :set-or-agg j :by by), without in-place changes.
  • Python's Polars: expressions are values you can store and combine, and comparisons with missing values are safe.
  • q/kdb+: time-series tools such as win/ratio, win/mavg, win/ema, win/fills and xbar, plus as-of and window joins.
  • Julia's DataFramesMeta.jl: #dt/e plays the role of @transform and @subset, using a Clojure reader tag.
